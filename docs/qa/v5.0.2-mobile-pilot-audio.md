# v5.0.2 — Mobile Pilot Audio

Date: 15 September 2026  
Baseline: `192338e0a342248c01561ede160ddf088554e257` (v5.0.1)  
Scope: web release; no Windows or Android package builds.

## Report and diagnosis

The user reported broken pilot speech during a mobile exercise while the opening headphone test remained clear. The device and browser were not identified.

The packaged reply recordings contain the middle words and heading digits. The runtime already assembles each reply into a single audio buffer. Two sequencing defects were reproduced in controlled tests:

- Recognition input was stopped synchronously, but its audio-context closure was asynchronous. Pilot playback could begin before that closure settled.
- A temporarily suspended pilot output context had no recovery path. The radio's wall-clock deadline could also expire while the audio clock was paused.

These are plausible contributors to the reported symptom, not a physical-phone reproduction of its cause.

## Changes

- Wait for pending microphone audio-context closures before starting the pilot reply.
- Resume transiently interrupted output from the same source position, without repeating the start of the message.
- Recalculate the reply deadline from the remaining audio after recovery.
- Keep recovery bounded. Failed audio falls back to the existing visible acknowledgement rather than holding the radio indefinitely.
- Ignore obsolete recovery callbacks after a new PTT command, cancellation, mute or replacement reply.

No flight physics, commands, procedure workflow, voice files, speech-speed choices or manual controls were changed. Headphone confirmation, muted default, controller priority and the existing continuous-listening quiet tail remain in place. Native project version metadata is aligned with the web release, but native binaries have not been generated.

## Repeat checks

Run the automated suite and build:

```sh
node --test packages/qgh-engine/test/*.test.js apps/web/test/*.test.mjs
node scripts/build-web.mjs
```

Serve `apps/web/dist` on loopback, then run `node scripts/qa-mobile-pilot-audio.cjs`. Set `QGH_QA_URL` for a different preview URL, and `QGH_PLAYWRIGHT_MODULE` if Playwright is installed outside the normal module search path. The detailed browser report is written to the ignored `artifacts/mobile-pilot-audio/report.json`.

## Phone follow-up

Check the page version is 5.0.2, connect headphones, complete the audio test and repeat the previously failing exercise call. Test both PTT and continuous listening, then interrupt one reply with a fresh PTT command. If speech still breaks up, record the phone model, operating-system/browser versions, headset type and which listening mode was active. Do not collect or upload users' microphone recordings automatically.
